# 1.3.1: schema errors at the right path

1.3.1 fixes two error messages. No values change: a value that 1.3.0 accepts renders the same, and one it rejects is
still rejected.

## What changed

- **Schema errors on a map's keys name the right path** ([ADR-0068](../adr/0068-schema-checks-on-map-keys-report-the-right-path.md),
  amending ADR-0011, ADR-0028, ADR-0038, ADR-0057 and ADR-0061). Helm's schema library stores a `propertyNames`
  failure with a location that a later sibling overwrites, so a reserved `podLabels` key failed `at '/prometheusRule'`.
  The schema has no `propertyNames` any more:
  - **a reserved key** is a false schema at its own path: `at '/podLabels/app.kubernetes.io~1name': false schema`;
  - **a name with a pattern** (environment variable names, ConfigMap keys, Secret keys) fails at its map's path:
    `at '/config': additional properties '1BAD' not allowed`. The message no longer prints the pattern or a Secret
    key's 253-character limit; the schema's descriptions state them.
- **`metrics.port` naming a sidecar's port** fails with one message, the end state: move that entry from
  `sidecars.<name>.ports` to `ports`. Before, one message asked to declare the port in `ports` and the next rejected the
  name declared twice.
- **`contract-keys.sh`** reads `patternProperties` as a map entry and skips a false schema under `properties`. It lists
  the same 653 keys from the 1.3.0 schema and the 1.3.1 one.

## Evidence

- **Unit tests:** 1481 (6 new, 44 updated): the 44 schema assertions now expect the key's own path or the map's; the
  new ones pin an entry's `env` name, an init container's `config` name, every reserved key of an extra object's labels
  and annotations, a Secret key of exactly 253 characters, and the `metrics.port` message.
- **Equivalence:** an independent verifier compared the accepted set of every changed map between the 1.3.0 schema and
  this one: 1,693 probes over the 20 changed maps, each rendered with both schemas on Helm 4.3.0 and 3.22.0 (6,772
  renders), gave the same accept or reject everywhere; the seven `ci/` scenarios render byte-identical output.
- **Native review** (risk, readability, reliability): approved with no blocking finding; its five suggestions are in
  the pull request.
- **The `--reuse-values` shape:** the 1.3.1 chart, rendered with 1.0.0's, 1.2.0's and 1.3.0's `values.yaml` as
  defaults, renders all seven `ci/` scenarios on Helm 4.3.0 and 3.22.0.
