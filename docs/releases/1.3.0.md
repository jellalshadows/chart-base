# 1.3.0: a per-volume Reloader opt-out

1.3.0 adds one optional key per `configMap` or `secret` volume, `volumes.<name>.reloadOnChange`. Values without it
render exactly as with 1.2.0.

## What changed

- **`volumes.<name>.reloadOnChange`** (`configMap` and `secret` entries). `false` leaves that volume's ConfigMap or
  Secret out of the Reloader annotations: the kubelet updates the mounted files in place, so a certificate the
  application re-reads no longer restarts the Deployment on every rotation. Before, the opt-out was all or nothing (the
  component's `reloadOnChange`) ([ADR-0067](../adr/0067-a-per-volume-reloader-opt-out.md), amending ADR-0033 and
  ADR-0049).
  - **Scope:** the top-level switch still wins. A ConfigMap or Secret that another source names, such as an `env`
    reference, stays in the annotations.
  - **Guard:** `false` fails when the main container or a sidecar mounts the volume with `subPath`. The kubelet never
    updates a `subPath` mount, so the change would reach that container only when the pod restarts. An init
    container's `subPath` is accepted, because the init container has exited before any change.
  - **Schema:** the key is a field of `configMap` and `secret` entries only; a non-boolean, or the key on another type,
    is rejected.
- **Optional** ([ADR-0064](../adr/0064-from-1-0-0-a-new-key-is-optional.md)): `null` and an absent key keep the
  volume in the annotations.

## Evidence

- **Unit tests:** 1474 (11 new), covering:
  - the volume left out of the annotations while the other volumes stay;
  - a Secret that an `env` reference names stays;
  - `null` as absent;
  - no annotation when every listed volume opts out;
  - the key never reaching the pod spec;
  - `subPath` rejected in the main container and in a sidecar, accepted in an init container;
  - `true` accepted with `subPath`;
  - the schema rejections.
- **The `--reuse-values` shape:** the 1.3.0 chart, rendered with 1.0.0's, 1.1.0's and 1.2.0's `values.yaml` as defaults,
  renders all seven `ci/` scenarios on Helm 4.3.0 and 3.22.0.
- **e2e on kind 1.33 and 1.37:** the existing scenarios pass unchanged. No scenario sets the key.
