# 0.12.0: execution record

This record keeps what happened while 0.12.0, the 1.0 contract, was designed, built and reviewed: the decisions and
the rulings with their reasons and their cost if wrong, the deviations from the design, the measurements, what was not
verified, and, once they exist, the final review's findings and the release. It is written for a reader who never saw
the working files of the execution; those files are named here by their role (the design, the rulings log, the feature
document), not by their location.

Roles: the **owner** of the repository authorized the execution to run without asking, merges and releases included
(the autonomous mode); the **controller** ruled on every question and dispatched every step; the **designer** wrote the
design; three **implementers**, one per batch of tasks, built the branch, each in a fresh context; the **reviewer**
reviews the whole branch and one **fix wave** applies its findings. Every one of them runs on the judgment model (Opus).

## What 0.12.0 is

The 1.0 contract: every decision that the roadmap held for the contract freeze, taken in one breaking release, so that
1.0.0 changes no contract. Nine of the design's 18 decisions are breaking: eight reject values that rendered with
0.11.0, and the ninth changes every pod template (one roll). The chart no longer writes `app.kubernetes.io/component`
(every Deployment rolls once); the main container's probes are closed like a sidecar's, with one rule per probe kind on
every container; the main container gets the checks of init containers and sidecars (a `lifecycle` port name, a
`subPath`, UID 0); `configFiles.mountPath` gets the token-directory rule of every mount; four metadata maps reject the
chart's and Helm's keys; `ingress.className` is required, `null` included; a PodDisruptionBudget must allow one
eviction at the replica floor. The freeze itself is
[ADR-0058](../adr/0058-the-1-0-contract-and-how-it-stays-frozen.md), `tests/contract_test.yaml` and the values key list
that CI checks. Documentation answers the rest of the first real umbrella's findings, and the README gets a dated
comparison with three other generic charts ([upgrade guide](../upgrading.md#011x--0120)).

## The release type: `feat!`

Values that rendered with 0.11.0 fail with 0.12.0 (each shape is measured in the upgrade guide), so the pull request is
`feat!`, which pre-1.0 gives 0.12.0 (`bump-minor-pre-major`). The design's squash title is `feat!: the 1.0 contract
(closed probes, reserved metadata keys, freeze checks)` with one footer line, `BREAKING CHANGE: values that rendered with
0.11.0 can fail; see docs/upgrading.md#011x--0120`: release-please keeps only the last footer line (the 0.11.0 lesson
A3). 1.0.0 is cut later by the owner with a `Release-As: 1.0.0` commit; how `Release-As` interacts with the
release-please `exclude-paths` is not verified and is checked before use.

## Decisions (the design)

| ID | Decision | Cost if wrong |
|---|---|---|
| D1 | One probe contract: `probes.<kind>` use the sidecars' definition (no `host`, no unknown field, a gRPC port a number); liveness and startup `successThreshold` at most 1 and no readiness `terminationGracePeriodSeconds` on every container; the main probes rendered without `null` fields ([ADR-0059](../adr/0059-one-probe-contract-for-every-container.md)) | A probe field Kubernetes accepts and the definition lacks fails at render; adding it is additive |
| D2 | A `lifecycle` hook's port name must be a `ports` entry | Low: such a name never resolved |
| D3 | A main-container `subPath` of a `configMap` or `secret` volume with `items` must name an item | Low: an empty directory was mounted |
| D4 | UID 0 with `runAsNonRoot: true` fails on the main container, the pod's UID included | Low: such a pod never started |
| D5 | `podLabels`, `podAnnotations`, `ingress.annotations`, `serviceAccount.annotations` reject the chart's and Helm's keys, through the 0.11.0 definitions ([ADR-0061](../adr/0061-reserved-metadata-keys-and-a-required-ingress-class.md)) | A legitimate key is rejected; the error's path names another key (documented) |
| D6 | `ingress.className` is required while the Ingress is enabled, `null` included | A cluster-default class needs an explicit name; accepting "no class" later is additive |
| D7 | `configFiles.mountPath` rejects the token directory whether or not the token is mounted ([ADR-0060](../adr/0060-the-main-container-takes-the-entries-checks-and-one-token-directory-rule.md), with D2-D4) | Low |
| D8 | A PodDisruptionBudget must allow one eviction at the replica floor, in all three scaling modes ([ADR-0062](../adr/0062-a-pdb-never-blocks-a-drain-at-the-replica-floor.md)) | A deliberately blocking PDB moves to `extraObjects` |
| D9 | No per-volume Reloader opt-out: the real umbrella did not ask | Adding it later is additive |
| D10 | The chart no longer writes `app.kubernetes.io/component` ([ADR-0063](../adr/0063-the-chart-does-not-write-app-kubernetes-io-component.md)) | Every Deployment rolls once; writing it again later is a major |
| D11-D14, D17 | Documentation: the version label follows the tag under a digest; the OpenTelemetry service identity; calling a sibling component; umbrella-wide defaults with YAML anchors; a Secret on the command line | An override key or a mechanism later is additive; reading `global` later is a major |
| D15 | Literal variables for an init container: deferred, the additive entry-level `config` | none |
| D16 | The real umbrella exercises the Deployment path only: no change; the umbrella lifecycle and the campaign cover CronJob and Job aliases | none |
| D18 | The freeze: ADR-0058, `tests/contract_test.yaml`, `contract-keys.sh` and its key list in CI | A forgotten contract item freezes by accident |

## Controller rulings

- **2026-11-17, the design accepted** with four rulings:
  1. **D10 option (b), ruled by the controller, not escalated.** Why: the label is not a selector label (nothing is
     recreated), its Kubernetes meaning is the component within the architecture, which the chart cannot know, and
     after 1.0 any change is a major; the only real consumer is the owner's own umbrella. Cost if wrong: every
     Deployment rolls once at the upgrade, and writing the label again later is a major. It is the ruling with the
     widest effect on consumers.
  2. **The comparison matrix states only verified facts**, with the versions and the check date, marks or drops a cell
     that was not checked, and ranks nothing. Why: these are public claims about other projects. Cost if wrong: a cell
     goes stale with the next release of another chart, which the date in the README bounds.
  3. **Three sequential fresh implementers**, no review per task or per batch, the controller's spot check between
     batches. Why: 11 judgment tasks with no plan code exceed one context; the owner's "one implementer, no per-task
     review" is kept in spirit. Cost if wrong: one extra reading of the design per batch.
  4. **The feature document lives outside the repository**, mirrored to the controller's memory. Cost if wrong: none
     for the release; the record you are reading carries its content.
- **2026-11-17, the pause and the resume:** batch B stopped after T7 at the owner's rule; on resume T8 joined batch C.
  Why: batch A carried four tasks in one context. Cost if wrong: a context stop in the middle of batch C, recoverable
  from the feature document and git.

## Judgment calls during the execution

Each was logged with its task and accepted for the final review to check.

- **T1:** `contract-keys.sh` resolves `$ref`, `allOf`, `anyOf`, `oneOf`, `then` and `else` and prints the paths a
  consumer writes (`ports[].name`, `volumes.<name>.subPath`), not the schema's raw paths, which would fail on an internal
  rename and miss a map pointed at another definition. Cost if wrong: 589 lines to review, and a key that only an `if`
  or a `not` names is not listed (none exists). An optional second argument names the keys file, for a packaged chart
  without `tests/` (the campaign checks the pulled chart). Cost if wrong: none.
- **T3:** the design's kind rules "on a sidecar and an init container" apply to sidecars only: an init container takes
  no probes, which the schema has rejected since 0.8.0. Cost if wrong: none. The unreachable not-a-map branch of the
  probe port check was removed (the design left keep or remove open). Cost if wrong: with
  `--skip-schema-validation` a handler that is not a map renders and the API server rejects it.
- **T4:** D2 reuses the probe port check with two optional inputs instead of a sibling helper (the hooks' shape is the
  probes'; a hook has no `tcpSocket`). D3 and D4 move the entries' inline checks into two helpers that the entries call
  too, so there are no two copies to drift. The UID check falls back to the pod's `runAsNonRoot`, as D4 says, which
  changes nothing for the entries. Three sidecar tests that set `podSecurityContext.runAsUser: 0` now give the main
  container its own UID, since the main container would fail first. Cost if wrong: none for each; every existing message
  is unchanged and pinned.
- **T5:** the converted hook-weight test became a rejection case plus a precedence case with a key that is not
  reserved, as the design said; one more test pins that a `null` class renders while the Ingress is disabled (the
  `required` sits in the enabled branch, not at the root); `helm.sh/resource-policy` stays accepted in
  `serviceAccount.annotations`, which the documented hand-over of the chart's ServiceAccount uses. Cost if wrong: none.
- **T6:** 15 cases instead of the design's 14: the measured `replicas: 1` with `"50%"`, and one accepting case each for
  the HPA and KEDA floors that `replicas` alone would reject, which make the floor's source observable. The guard sits
  in `validate.yaml` with every other guard. A `minAvailable` or `maxUnavailable` string that is not a percentage is left
  to the API server. Cost if wrong: none; a later `scaling_test` case that trips another guard errors with its message.
- **T7:** `readme-recipes.sh` reads the generated `README.md`, not the template, whose helm-docs escapes are not what a
  consumer pastes (CI's drift check keeps the two equal); it reads the schema locations from `validate-manifests.sh`
  instead of a second copy; an optional output directory keeps the umbrellas for the campaign; a top-level key starting
  with `x-` is the anchor holder, not an alias. Cost if wrong: a recipe with another key that is not an alias fails
  loudly.
- **T8:** the command-line Secret recipe uses `externalSecretKeyRef` (the shape the real umbrella ran) and says that a
  `secretKeyRef` works the same; the version-label note sits in that Redis recipe and in the values table, not in a
  recipe of its own; the OpenTelemetry recipe keeps its heading, which the consuming guide links. Cost if wrong: none.
- **T9:** the upgrade check of `E2E_UPGRADE_FROM` compares every release object's uid and selector and prints each
  Deployment's revisions instead of asserting that it rolled exactly once: the count depends on the older version.
  The umbrella lifecycle pins that a rollback runs no Job hook (the hooks are `pre-install,pre-upgrade`) and that the
  hook Job outlives an uninstall ([ADR-0007](../adr/0007-jobs-as-helm-hooks.md)). With `REF`, the signing checks read
  the overwrite guard's headers by digest. Cost if wrong: an extra roll shows only in the log; adding rollback hooks
  later changes the check on purpose; the tag-to-digest mapping of a new release is not checked there.
- **T10:** nxs-universal-chart was checked at 3.2.4, published on its registry on 2026-11-13, from the package: its
  repository has no tag after `v3.2.2` that day, and the CI cell says it describes `v3.2.2`. Its cell on a missing CRD
  states the one fact checked. Cost if wrong: a reader compares a CI cell of an older version, which the cell says.
