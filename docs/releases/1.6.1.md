# 1.6.1: guards accept what they ignore, and a `--reuse-values` check in CI

1.6.1 accepts two values that 1.6.0 rejects and adds checks. Every value that renders on 1.6.0 renders the same
manifest, with the same guards and messages.

## What changed

- **A `statefulset` member that its nulls leave empty is unset on other workload types**
  ([ADR-0071](../adr/0071-a-statefulset-workload-type-with-a-claim-per-pod.md)).
  - `statefulset.updateStrategy: {rollingUpdate: {partition: null}}` now renders on a deployment, cronjob or job, the
    same as when the member is absent, as `{}` already did. Before, the guard tested emptiness one level deep only.
  - A member that is set still fails with the 1.6.0 message.
  - The OnDelete `rollingUpdate` guard keeps its `hasKey` check.
- **The Recreate + `rollingUpdate` guard applies to deployments only**, as ADR-0071 says.
  - `strategy: {type: Recreate, rollingUpdate: {}}` now renders on a statefulset, cronjob or job, which ignore
    `strategy`.
  - The schema now describes `strategy` and `progressDeadlineSeconds` as Deployment only.
  - Rejecting them on the other types would reject values that render on 1.6.0. That waits for a major: see the
    roadmap's new "Waits for a major" section.
- **The alias contract checks the `--reuse-values` shape.** CI renders the chart with the `values.yaml` of v1.0.0 and
  of the previous release as its defaults, and checks two things:
  - every `ci/` scenario renders the same as with the chart's own defaults;
  - each of the 12 keys added since 1.0.0 that have a default renders, when set to `null`, the same as when absent.
- **The testing guide has a new rule:** schema errors come in no fixed order. Helm 3.22.0 and 4.3.0 embed
  santhosh-tekuri/jsonschema v6.0.3, which ranges over a Go map, so an assert matches one error only.

## Evidence

- **Unit tests:** 1740 (19 new).
  - Written test-first for both guard fixes.
  - The two null-variable tests for the external Secret's reader guard cannot fail first, because the chart already
    behaves correctly. A mutation check proves them instead: each test fails when its half of the guard is mutated.
- **The alias contract's new layer:**
  - It passes in CI on Helm 4.3.0 and 3.22.0, over v1.0.0 and v1.6.0.
  - It fails against the 1.4.0 chart and against a template-only null regression made on purpose.
- **Differential against 1.6.0:** 92 cases × 2 Helm versions. 24 renders differ, all of them newly accepted values,
  each byte-identical to the render with the member or key absent.
- **Contract keys:** 698, unchanged.
- **Native review** (risk, reliability, readability): approved and acknowledged; its nine findings are informational.
