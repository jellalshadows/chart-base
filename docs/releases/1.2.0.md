# 1.2.0: literal variables for init containers and sidecars

1.2.0 adds one optional key per entry, `initContainers.<name>.config` and `sidecars.<name>.config`. Values without it
render exactly as with 1.1.0.

## What changed

- **`config` on an init container or a sidecar:** the entry's own literal variables, `NAME: value` (a string, a number
  or a boolean). Before, a literal reached an entry only through `args`, or through `inheritEnv`, which brings the main
  container's whole environment. The first real umbrella's finding G4, deferred by 0.12.0
  ([ADR-0066](../adr/0066-an-entry-level-config-for-literal-variables.md), amending ADR-0051).
  - **Rendering:** the literals go in the entry's `env` after its references, sorted by name. They are converted to
    strings as the component's `config` is, through one shared helper (`chart-base.configValue`); the ConfigMap's
    output is unchanged. They come after the references, so a literal can use `$(NAME)` of a reference.
  - **Guards:**
    - a name in both the entry's `env` and its `config` fails;
    - with `inheritEnv: true`, a `config` name the main container already receives fails.
  - **Messages:** a literal in an entry's `env` now names the entry's `config` in its remedy.
- **Optional** ([ADR-0064](../adr/0064-from-1-0-0-a-new-key-is-optional.md)): `null` and an absent key render
  no variable.

## Evidence

- **Unit tests:** 1463 (11 new), covering:
  - rendering on an init container and on a sidecar;
  - the order and the string conversion (`10000000` stays `"10000000"`);
  - `null` and `{}`;
  - `inheritEnv` with `config`;
  - schema rejections, both guards, and the two updated remedies.
- **The `--reuse-values` shape:** the 1.2.0 chart, rendered with 1.0.0's and with 1.1.0's `values.yaml` as defaults,
  renders all seven `ci/` scenarios on Helm 4.3.0 and 3.22.0.
- **e2e on kind 1.33 and 1.37** (the `full` scenario, Helm 4.3.0):
  - the sidecar `shipper` has `POD_NAME` (a `fieldRef`) and the literals `SHIPPER_MODE: e2e` and
    `SHIPPER_SOURCE: "pod-$(POD_NAME)"`;
  - the job reads `shipper`'s `/proc/1/environ` and finds `SHIPPER_MODE=e2e` and `SHIPPER_SOURCE=pod-<pod name>`, the
    kubelet's expansion;
  - both jobs print `ok - full: the sidecar shipper receives the literals of its config, one built from its reference
    with $(POD_NAME)`.
