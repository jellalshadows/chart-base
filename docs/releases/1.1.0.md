# 1.1.0: the handover from the HPA to KEDA

1.1.0 adds one optional key, `autoscaling.kedaHandover`, and the rule that from 1.0.0 a new key is optional. Values
without the key render exactly as with 1.0.0.

## What changed

- **`autoscaling.kedaHandover`** (`false` by default): `true` puts `validations.keda.sh/hpa-ownership: "false"` on
  the chart's HPA. KEDA's admission webhook skips an HPA with that annotation (KEDA v2.21.0,
  `apis/keda/v1alpha1/scaledobject_webhook.go`, `verifyHpas`). Once the HPA carries it, the switch to KEDA
  (`autoscaling.enabled: false`, `keda.enabled: true`) takes one upgrade. Before, it took `kubectl delete hpa` or two
  upgrades through `replicas`. The annotation is the HPA's per-object map, so it wins over the same key in
  `commonAnnotations`. There is no guard: the key is read only while the HPA is on
  ([ADR-0065](../adr/0065-an-opt-in-handover-from-the-chart-s-hpa-to-keda.md), amending ADR-0056).
- **From 1.0.0, a new values key is optional** ([ADR-0064](../adr/0064-from-1-0-0-a-new-key-is-optional.md), amending
  ADR-0027). A required key would fail a direct install upgraded with `--reuse-values` (`missing property`), which a
  minor may not do. The templates read an absent key as its default.

## Evidence

- **Unit tests:** 1452 (7 new). The annotation is absent by default and for `null`, present with the key, wins over
  `commonAnnotations` while the other common keys stay, and is not rendered without an HPA. A non-boolean value is
  rejected.
- **The `--reuse-values` shape:** the 1.1.0 chart rendered with 1.0.0's `values.yaml` as its defaults, the seven `ci/`
  scenarios on Helm 4.3.0 and 3.22.0, all render and none carries the annotation.
- **e2e on kind 1.33 and 1.37** (the keda scenario, KEDA 2.21.0, Helm 4.3.0): after the switch back to the chart's HPA,
  an upgrade sets the key and the live HPA carries the annotation. One upgrade then switches to KEDA: the webhook
  admits the ScaledObject, it becomes Ready, KEDA's HPA targets the Deployment, and the chart's HPA is gone. Both jobs
  print `ok - keda: with autoscaling.kedaHandover, one upgrade switches from the chart's HPA to KEDA`.
